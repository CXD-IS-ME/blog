Go 并发模型 GMP：为高并发做准备

Go 并发模型 GMP：为高并发做准备

引言

Go 语言以其出色的并发支持而闻名，这得益于其独特的 GMP 并发模型。理解 GMP 模型对于编写高效的并发程序至关重要。本文将深入解析 GMP 模型的原理和工作机制。

知识点概览

1. GMP 模型概述

GMP 是 Go 语言运行时的并发调度模型：

  • G（Goroutine）：轻量级线程，由 Go 运行时管理
  • M（Machine）：操作系统线程
  • P（Processor）：处理器，负责调度 Goroutine

2. Goroutine

Goroutine 是 Go 语言中的轻量级执行单元，相比操作系统线程，Goroutine 更加轻量：

  • 初始栈大小约 2KB
  • 可以动态扩展收缩大小
  • 创建和切换开销低

3. M 和 P 的关系

  • M 是真正执行代码的操作系统线程
  • P 是处理器，包含运行 Goroutine 所需的上下文
  • M 必须绑定一个 P 才能执行 Goroutine

4. GOMAXPROCS

runtime.GOMAXPROCS(n) 设置同时执行 Goroutine 的最大 CPU 核心数。

  • P（Processor）：处理器，管理 Goroutine
  • 使用 runtime.GOMAXPROCS() 设置并发度

常见并发 Bug 与预防

常见并发 Bug 与预防

引言

并发编程是 Go 语言的核心优势，但并发 Bug 也更容易出现。本文将介绍常见的并发 Bug 类型，包括数据竞争、死锁、闭包陷阱等，并提供相应的预防方法。

知识点概览

1. 数据竞争

多个 goroutine 同时访问共享数据，至少有一个是写操作。

2. 死锁

两个或多个 goroutine 互相等待对方释放资源。

3. 闭包陷阱

在循环中创建 goroutine 时，闭包捕获的变量可能是共享的。

4. Map 并发写入

Go 的 map 不支持并发写操作。
